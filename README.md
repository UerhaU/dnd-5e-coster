# Костёр — D&D 5e

**v0.1.0-alpha.1 — ранний прототип / каркас приложения.**

Имя репозитория: `dnd-5e-coster`.

Локальное русскоязычное веб-приложение для D&D 5e редакции 2014 года.
Планируемый охват: персонажи, кампании, инвентарь, магия и инструменты мастера.

## Текущее состояние

Созданы каркас интерфейса, основа локального сервера и базы, инструменты импорта DnD.su.
Игровые экраны и обработчики находятся на стадии незавершённых прототипов.
Эта публикация фиксирует начало разработки; приложение пока не готово для проведения игры.
Наличие экрана или кнопки не означает работающий и проверенный игровой сценарий.

Актуальные ограничения: [сводка готовности](docs/current-status.md).
Целевое поведение: [техническое задание](docs/dnd5e_2014_interactive_app_spec.md).

## Локальный запуск

Нужны Node.js с npm. Проект разрабатывается на Node.js 24 под Windows.

```powershell
npm ci
Copy-Item .env.example .env
npm run db:push
npm run dev
```

Копирование `.env` выполняется при первой установке; существующий локальный файл сохраняйте.
Интерфейс: http://localhost:5173, API: http://localhost:3000.
Локальная база создаётся в `storage/`.

Демонстрационные профили: `ERHA` и `ERHACHECK`, пароль обоих — `demo`.
Локальные переопределения можно задать в исключённом из Git файле `.env.local`
через переменные из `.env.example`. После изменения перезапустите Vite.

Вход в профиль — временный механизм прототипа в браузере.
Значения `VITE_*` доступны в клиентской сборке и не обеспечивают защиту доступа.
Сервер разработки слушает сетевые интерфейсы; используйте доверенную локальную среду.
Публичное размещение работающего сервера не поддерживается этой версией.

## Справочные данные

Книги, готовая база, скачанные страницы и импортированный контент в репозиторий не включены.
Без локального каталога справочные списки будут неполными или пустыми.
Инструмент загрузки каталога запускается отдельно и требует интернета:

```powershell
node scripts/import-dndsu-catalog.mjs
```

Наличие импортированных записей не означает автоматизацию соответствующих правил.
Импорт данных не меняет права на исходные материалы.

## Проверка перед публикацией

```powershell
npm run release:check -- --list
```

Команда показывает файлы, которые Git сможет включить: уже отслеживаемые и новые,
не исключённые через `.gitignore`. Она также работает до `git init`.
Если среди них найдены книги, локальные настройки, базы, кэши или сборки, проверка завершится ошибкой.
Проверка касается путей и типов файлов; содержимое изменений нужно просмотреть отдельно.

В `.gitignore` исключены `book/`, локальное содержимое `storage/`, `.env*`
(кроме `.env.example`), локальные заметки, зависимости, сборки, журналы,
PDF и другие форматы книг, установщики, архивы и файлы ключей.
Эти правила сохраняют файлы на компьютере.

После подготовки первого коммита проверьте его состав и содержимое:

```powershell
git add --dry-run .
git add .
git diff --cached --stat
git diff --cached
npm run release:check
```

Уже отслеживаемые файлы не исключаются автоматически после изменения `.gitignore`.
Не используйте `git add -f` для локальных материалов.

Для первого GitHub Release используйте тег `v0.1.0-alpha.1`, название
**«v0.1.0-alpha.1 — каркас приложения»** и отметку **Pre-release**.
В описании укажите, что это снимок ранней разработки и игровые сценарии не готовы.
