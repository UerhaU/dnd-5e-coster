## UI-срез

- Интерфейс переведен в формат игрового главного меню.
- Главное меню содержит:
  - `Подключиться к кампании`;
  - `Создать персонажа`;
  - `Просмотр персонажей`;
  - `Создать кампанию`;
  - `Просмотр кампаний`;
  - `Настройки`.
- Переключение режима `Мастер` / `Игрок`.
- Выбор локального профиля.
- Мастер может создать кампанию.
- Мастер может редактировать название, описание и сеттинг кампании.
- Мастер может создать комнату в выбранной кампании.
- Мастер может редактировать название и статус комнаты.
- Игрок видит, что он не создает комнаты самостоятельно.
- Игрок может выбрать своего персонажа и войти в открытую комнату.
- В комнате отображаются участники и выбранные персонажи.
- Выбранный профиль может создать персонажа.
- HP персонажа меняются через API и автосохраняются.
- Отображаются локальные книги-источники из папки `book`.
- Мастер может включать и выключать книги-источники для выбранной кампании.
- Мастер может добавлять персонажей в партию и убирать их из партии.
- Отображаются последние локальные сохранения по выбранной кампании.
- Просмотр персонажа показывает базовую версию из меню и отдельные версии в кампаниях.

## Серверное состояние персонажа в кампании

- Базовый персонаж хранится в библиотеке игрока.
- Прогресс персонажа в кампании хранится на сервере в `CampaignCharacterState`.
- Один персонаж может иметь разные состояния в разных кампаниях.
- Сопоставление идет по ID персонажа и ID кампании.
- Сейчас сервером выступает локальный backend на ПК пользователя/мастера.
- В следующих сетевых этапах этот же ПК должен выступать сервером для игроков в LAN.

## Добавлено как подготовка к LAN/realtime

- Добавлен backend endpoint `GET /api/network/info`.
- Endpoint возвращает:
  - локальный frontend/backend URL;
  - найденные LAN-адреса;
  - список будущих realtime-событий;
  - допустимые статусы участника комнаты: `joined`, `online`, `offline`, `left`, `reconnecting`.
- Добавлен backend endpoint `PATCH /api/campaigns/:campaignId/characters/:characterId/hp`.
- HP теперь меняется именно в `CampaignCharacterState`, то есть в серверном состоянии персонажа внутри кампании, а не в базовой библиотечной копии.
- Добавлен backend endpoint `PATCH /api/rooms/:roomId/participants/:participantId/status`.
- Frontend API-вызовы вынесены в `src/api.ts`.
- В просмотре кампании мастер видит:
  - код подключения;
  - LAN-адрес для второго устройства.
- В просмотре кампанийного состояния персонажа добавлены быстрые кнопки `-1` / `+1` HP для smoke-проверки будущей realtime-синхронизации.

## Минимальный realtime-контракт для следующего этапа

- `room:joined` — игрок вошел в комнату.
- `room:left` — игрок вышел из комнаты.
- `room:participant-status` — изменился статус подключения игрока.
- `character:hp-updated` — изменились HP персонажа в кампании.
- `campaign:snapshot-created` — создано автосохранение.
- `room:refreshed` — комната требует обновить состояние.
