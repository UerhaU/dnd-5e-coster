# Проверка карточки заклинания

Откройте [База заклинаний.accdb](../База%20заклинаний.accdb). Стартовая форма — **КаталогЗаклинаний**. Если она не открылась автоматически, найдите её в разделе «Формы».

Выберите название сверху. Карточка показывает уровень/школу, время, дистанцию, длительность, ритуал/концентрацию, компоненты, краткое описание, усиление, формулу/эффект, материалы и классовую доступность. Ниже страницы есть ссылка на исходную карточку. Для нижних разделов используется вертикальная прокрутка.

Поля карточки заблокированы для редактирования; список выбора остаётся доступным. На основной форме `AllowEdits = True`, иначе Access блокирует и несвязанный список. Добавление и удаление записей запрещены; связанные подформы только для чтения. Вся информация берётся из связанных таблиц; отдельной вручную заполненной копии карточки нет. Пустой список материалов у Лечения ран — правильный результат: у него только В и С.

| Заклинание | Что удобно проверить | Источник |
| --- | --- | --- |

| Опознание | Ритуал, минута накладывания, жемчужина от 100 зм и перо совы; материалы сохраняются | [DnD.su](https://5e14.dnd.su/spells/210-identify/) |
| Благословение | Концентрация до минуты, до трёх целей, добавление к4, капля святой воды, усиление числа целей | [DnD.su](https://5e14.dnd.su/spells/9-bless/) |

Описание — краткий пересказ механики 2014 года. Полная карточка источника доступна по ссылке. Класс в списке не означает автоматически изученное заклинание; подклассы и дополнительные источники показаны отдельно.

В форме используется штатный макрос Access `SearchForRecord` с обновлением связанных подформ. VBA-модулей и внешних исполняемых файлов в базе нет. Настройки доверия или безопасности Access не менялись. Программные проверки проходили и при `CurrentProject.IsTrusted = False`.

После сообщения пользователя исправлена привязка списка: форма фактически использовала `BoundColumn = 2` (название), хотя поиск ожидал ID. Причина — различие индекса в текстовом формате формы и в API Access. Исправлен также генератор формы. До исправления новый тест воспроизводит ошибку: [отчёт регрессии](../database/spells/selector-regression-before-fix.json).

Программно проверены начальное название в поле, все четыре строки списка и повторные переходы: основная запись, параметры, эффекты, классы/подклассы и материалы меняются вместе. Тест берёт фактическое связанное значение строки через `ItemData`, проверяет `ListIndex` и отображаемый `Text`, затем отдельно запускает макрос, зарегистрированный в `AfterUpdate`: присваивание через COM само событие не вызывает. Предыдущая проверка подставляла ID напрямую и потому пропустила ошибку. Проверены также чтение текста, отсутствие технических ключей, границы элементов и запрет редактирования данных из карточки. [Отчёт формы](../database/spells/player-form-verification.json), [отчёт данных](../database/spells/demo-data-verification.json).

Второе сообщение пользователя выявило блокировку списка общим `AllowEdits = False`, которую программное присваивание обходило. Исправление сохранено в основной базе и генераторе; новый тест проверяет разрешение выбора и блокировку полей отдельно. [Регрессия до исправления](../database/spells/selector-lock-regression-before-fix.json).

15.10.2026 выполнена короткая проверка мышью: из раскрытого списка выбран «Огненный шар», автоматически обновились название, уровень, дистанция, бросок и материалы. Макрос вручную при этой проверке не запускался. Пользователь затем подтвердила: «Работает». Это подтверждает исправление выбора; приёмка всей базы и всего внешнего вида отдельно не заявляется. По остановке пользователя дальнейшие действия computer-use прекращены.
