# Этап 3: LAN/realtime

> Актуализация 2026-10-15: это историческая запись о прототипе, не завершённый и не принятый игровой этап. Старые заявления `completed`/`implemented` ниже не подтверждают готовность. Текущая оценка: [сводка готовности](./current-status.md).

Дата обновления: 2026-05-02

## Цель

Проверить рабочую модель "ПК мастера как локальный сервер": мастер открывает комнату на своем компьютере, второй компьютер в той же сети подключается как игрок, выбирает персонажа и видит обновления комнаты без ручного обновления страницы.

## Что реализовано

- Backend и frontend уже запускаются на `0.0.0.0`.
- Backend отдает сетевую диагностику через `GET /api/network/info`.
- Мастерский экран показывает:
  - код подключения комнаты;
  - LAN-адрес frontend для второго устройства;
  - состояние realtime-синхронизации.
- Добавлен WebSocket endpoint:
  - `ws://<host>:3000/ws/rooms/:roomId?userId=:userId`.
- Frontend автоматически подключается к WebSocket активной комнаты.
- Vite proxy можно направить на другой backend через `VITE_API_TARGET`, например `http://localhost:3001`.
- При WebSocket-подключении участник комнаты переводится в статус `online`.
- При закрытии последнего WebSocket-соединения пользователя участник переводится в `offline`.
- Игрок после подключения по коду сразу переходит в просмотр кампании.
- Список игроков в комнате показывает статусы подключения.
- Игрок может явно нажать `Выйти из кампании`.
- Выход не удаляет персонажа и прогресс, а переводит участника комнаты в статус `left`.
- Изменение HP через `PATCH /api/campaigns/:campaignId/characters/:characterId/hp` рассылает realtime-событие всем подключенным клиентам комнаты.
- Frontend слушает события комнаты и обновляет данные без ручного refresh.

## Realtime-события

- `room:connected` — клиент подключился к каналу комнаты.
- `room:joined` — игрок вошел в комнату.
- `room:left` — игрок явно вышел из комнаты/кампании.
- `room:participant-status` — изменился online/offline/reconnecting/status участника.
- `character:hp-updated` — изменились HP персонажа в кампании.
- `campaign:snapshot-created` — зарезервировано для будущего журнала автосохранений.
- `room:refreshed` — комната требует обновить состояние.

## Минимальная ручная проверка

1. Запустить проект через `npm run dev`.
2. На ПК мастера открыть `http://localhost:5173`.
3. Создать или загрузить кампанию.
4. В просмотре кампании найти LAN-адрес и код подключения.
5. На втором устройстве в той же сети открыть LAN-адрес.
6. Создать или выбрать персонажа.
7. Ввести код подключения.
8. Убедиться, что игрок появился в списке игроков комнаты.
9. Изменить HP кампанийной версии персонажа через кнопки `-1` / `+1`.
10. Проверить, что второе устройство увидело изменение без ручного обновления страницы.
11. На втором устройстве нажать `Выйти из кампании`.
12. Проверить у мастера, что участник получил статус `Вышел`.

Если порт `3000` уже занят старым backend-процессом, можно поднять отдельный Stage 3 стек:

- backend в PowerShell: `$env:PORT='3001'; $env:HOST='0.0.0.0'; npm run dev:backend`;
- frontend в PowerShell: `$env:VITE_API_TARGET='http://localhost:3001'; npm run dev:frontend -- --host 0.0.0.0 --port 5175`.
