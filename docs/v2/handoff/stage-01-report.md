### Issue #6 — `npm run catalog:build`

- `npm run catalog:build` — полный каталог; `-- --fixtures` — тестовый; `--fresh` — без прошлого `catalog.db` (номера из журнала); `--no-ledger` — без журнала; `--strict` — код 1 при ошибках.
- Ревизии прошлой сборки переносятся как есть; новая — только если изменились `data_json` или `rules_json` (SHA-256 канонического JSON). Пропавший объект остаётся с ревизиями и пометкой `withdrawn`.
- `catalog_info`: `catalog_version` растёт только при изменениях, `content_hash`, `built_at`, `importer_version`, `source_site`, `source_checked_on`, `source_kind`.
- Защита истории: перед заменой прошлая сборка копируется в `storage/backups/catalog/`; тестовый каталог отказывается заменить полный без `--force`; номера ревизий хранит журнал в git (часть Б).

### Часть Б: журнал ревизий в git (Р51)

- Папка `data/catalog-ledger/`: `spell.jsonl` — по строке на ревизию (`revisionId`, `entityId`, `revision`, `contentHash`, `schemaVersion`, `importerVersion`, `createdAt`), по порядку ID; `catalog.json` — версия каталога, хеш, дата сборки. Текстов DnD.su нет (Р47). Сейчас 525 строк, 131 КБ.
- Почему `data/catalog-ledger/`, а не `data/reviewed/`: журнал пишет сборка, а не человек; лежит рядом с `reviewed/` и `fixtures/`, в git. По файлу на категорию (`spell.jsonl`, потом `item.jsonl`…); в `git diff` видны ровно новые ревизии.
- Полная сборка читает журнал вместе с прошлым `catalog.db` и перезаписывает его. Если `catalog.db` нет, неизменившийся объект получает ту же ревизию (ID, номер, дату) из журнала, изменившийся — следующий номер; версия и дата каталога тоже берутся из журнала. Прошлые ревизии без текста восстановить нельзя: их номера заняты, в каталоге их нет (предупреждение в отчёте сборки). Расхождение журнала с `catalog.db` — ошибка сборки.
- Тестовый каталог (`--fixtures`) журнал не читает и не пишет.
- **После каждой полной сборки журнал нужно коммитить** вместе с изменениями `data/reviewed/`.

### Issue #8 — API каталога и схемы Zod

| Маршрут | Что делает |
| --- | --- |
| `GET /api/catalog/categories` | категории и число объектов (снятые не считаются) |
| `GET /api/catalog/spell?q=&page=&pageSize=&level=&school=&class=&source=&ritual=&concentration=&sort=` | список: поиск, фильтры, сортировка `relevance`/`name`/`level`, страницы (по умолчанию 25, максимум 100) |
| `GET /api/catalog/spell/facets` | значения фильтров с подписями и числом заклинаний |
| `GET /api/catalog/entity/:id` | карточка: все поля `spell/v1`, правила, источники со ссылкой на DnD.su, статус, ревизия и список ревизий |
| `GET /api/catalog/entity/:id/revisions/:rev` | та же карточка для ревизии с номером `rev` |
| `GET /api/health` | + `catalog: { version, contentHash, builtAt, sourceKind }` или `null` |

- Схемы запросов и ответов — `packages/shared/src/api/catalog.ts`; общий клиент — `api/client.ts` (`createApiClient`, каждый ответ проверяется схемой); формат ошибки — `api/errors.ts`: `{ error: { code, message, details? } }`, коды `bad_request` (400), `not_found` (404), `catalog_unavailable` (503, программа без каталога), `internal` (500). Неизвестный адрес и лишний параметр запроса тоже отвечают в этом формате.
- Запросы к базе — `packages/db/src/catalog/spell-queries.ts` (SQL: фильтры собираются из частей, FTS5 Drizzle не описывает). Маршруты — `packages/server/src/routes/catalog.ts`, ошибки — `packages/server/src/errors.ts`.
- Снятые (`withdrawn`) объекты не попадают в список и фильтры, но карточка и ревизии открываются (Р21).

## Что важно знать следующему этапу

- **Журнал ревизий:** после полной сборки коммитить `data/catalog-ledger/`. Новая категория получает свой файл сама (по началу ID: `item:…` → `item.jsonl`).
- **API пока знает одну категорию.** `GET /api/catalog/:category` и `/facets` проверяют `category === 'spell'` (`requireSpellCategory` в `packages/server/src/routes/catalog.ts`). Этапу 2 — свои запросы по образцу `spell-queries.ts` и выбор по категории; `readEntity` и маршруты карточки общие, но ответ проверяется `spellEntityResponseSchema` — нужна общая схема с вариантом по категории.
- **Категории:** `CATEGORIES` в `packages/shared/src/catalog/entity.ts`; название категории — `CATEGORY_NAMES_RU` в `spell-queries.ts`; буква-заглушка — `CategoryIcon` в `packages/ui`.
- **Тесты сервера** на временном каталоге: `openTestCatalog()` из `packages/server/src/test/test-catalog.ts`.
- **Экраны:** стили — только токены из `packages/ui/src/theme/tokens.css`; подписи — чистые функции с тестами (как `catalog/spell-format.ts`); запросы — только через `useApi()` и TanStack Query; новые экраны — в `createHashRouter` в `packages/ui/src/App.tsx`.
- **Код, который запускает Node** (`shared`, `db`, `importer`): без `enum` и свойств в параметрах конструктора — `erasableSyntaxOnly` это проверяет.
- **Playwright:** собрать программу во внешнюю папку (обход `EBUSY`), затем `KOSTER_APP_DIR=<папка>\win-unpacked npm run e2e`.
- В рабочей папке `apps/desktop/resources/catalog.db` — полный каталог версии 2. Не собирать поверх него `--fixtures` (команда откажется без `--force`).
