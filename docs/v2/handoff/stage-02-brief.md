## Цель

Две новые категории каталога по образцу заклинаний: **обычное снаряжение** (оружие, доспехи, щиты, снаряжение искателя приключений, наборы, инструменты, боеприпасы) и **расы с разновидностями** — с механикой, которая понадобится конструктору персонажа (этап 4). Плюс то, что появляется, когда категорий больше одной: поиск по всему каталогу (Р54), общая карточка и связи между объектами.

## Порядок работы

Три части, **каждая в своём чате**, промежуточный отчёт `docs/v2/handoff/stage-02-report.md` после каждой:

- **Часть А — снаряжение**: данные, API, экраны.
- **Часть Б — расы**: данные, API, экраны.
- **Часть В — общее**: поиск по всему каталогу, связи заклинаний с предметами, выборка для автора.

Ответы автора на вопросы — в конце брифа (Р60, Р61).

## Входит в этап

Общее для А и Б:

- Схемы Zod `item/v1` и `race/v1` (+ механика в `rules_json`, по образцу `spell-rules/v1`), таблицы `item_index` и `race_index` для фильтров, справочники, которых не хватает (виды оружия и доспехов, свойства оружия, размеры, типы существ).
- Импорт по цепочке раздела 6, ID по Р11 (`item:longsword`, `race:hill-dwarf`), фильтр редакции Р12, журнал ревизий `data/catalog-ledger/item.jsonl` и `race.jsonl` (Р51), тестовые страницы в `data/fixtures/` (несколько на случай, не весь каталог — Р47), тестовый каталог в CI.
- **Кэш.** В `storage/imports/cache/dndsu-pages/` 934 страницы `dnd.su/items/…` — это **магические** предметы, они в этап не входят. Обычное снаряжение на DnD.su — статьи-таблицы «Снаряжение» (в v0.1: `storage/legacy-v0.1/database/equipment/inventory.html`, `firearms.html` и разобранные таблицы). Расы — `5e14.dnd.su/race/…`; в кэше только 3 (`storage/race-samples/`). Недостающие страницы скачать `catalog:fetch` (1–2 запроса в секунду), выбранный кэш и даты — в отчёт.
- API по разделу 7 для новых категорий: `/api/catalog/item`, `/api/catalog/race`, `facets`; общая схема карточки с вариантом по категории (сейчас `spellEntityResponseSchema`, см. отчёт этапа 1).
- Экраны «Справочника»: «Снаряжение» и «Расы» — список с фильтрами и карточка, на временной теме, по образцу заклинаний. Тексты — без вставки HTML.
- Тесты парсеров на fixtures, тесты API на временной базе, Playwright: по одному сценарию на категорию.

Часть А — снаряжение:

- Оружие: категория (простое/воинское, рукопашное/дальнобойное), урон и тип, свойства (фехтовальное, универсальное с уроном двумя руками, метательное, дистанция, боеприпас, перезарядка, особое), цена, вес. Доспехи и щит: вид, формула КД (база, модификатор Ловкости, предел), требование Силы, помеха Скрытности, время надевания и снятия, цена, вес.
- Снаряжение искателя приключений, наборы (с составом — ссылками на предметы), инструменты, боеприпасы, транспорт и товары — если есть на DnD.su в статьях 2014.
- Дополнительное оружие и огнестрельное оружие DMG — с пометкой «вариант правил, нужно разрешение мастера» (как в v0.1).
- Проверенные правила доспехов из `armor-reviewed-rules.mjs` → `data/reviewed/items/`.
- Цена — в медных монетах (1 зм = 100 мм, как `costCp` у заклинаний); неизвестное — `null`.

Часть Б — расы:

- Раса и разновидности (дварф → холмовой, горный) как отдельные объекты со связью `variant_of`; что общее — у расы, что своё — у разновидности, без дублей (ловушка v0.1: у дварфа особенности повторяются в разновидностях).
- Механика в `rules_json`: увеличение характеристик (фиксированное и «на выбор»), размер, скорости (ходьба, полёт, плавание, лазание), тёмное зрение, владения (навыки, оружие, доспехи, инструменты), языки (фиксированные и на выбор), сопротивления. Выборы игрока — как выборы, а не как готовое значение. Особые умения (дыхательное оружие и т. п.) — текстом, `automation: display_only`, если их нельзя честно описать данными.
- Навыки, инструменты и языки — пока кодами без проверки ссылки (их каталог — этап 3), как классы у заклинаний; записать в отчёт как долг этапа 3.
- Возраст, рост, вес — как на странице DnD.su (см. вопрос к автору).

Часть В — общее:

- **Поиск по всему каталогу** (Р54): `GET /api/catalog/search`, одна строка поиска в «Справочнике», результаты с пометкой категории, точное совпадение названия — первым.
- **Связи заклинаний с предметами** (долг этапа 1): материальные компоненты из `data/reviewed/spells/` получают ссылки `content_links` (`material_component`) на предметы каталога, где предмет есть. Что делать с компонентами, которых нет в списках снаряжения (гуано летучей мыши, алмаз за 300 зм), — см. вопрос к автору.
- Выборка для автора: по 15 предметов и 15 рас/разновидностей на сложные случаи — файлом в `docs/v2/handoff/`, по образцу `stage-01-spell-sample.md`. Проверку выборки потом делает чат «Тестирование».

## Не входит в этап

- Магические предметы (934 страницы `dnd.su/items/`) — этап 6 (раздел 6, пункт 6).
- Классы, предыстории, черты, навыки, языки, инструменты как объекты каталога — этап 3.
- Изображения снаряжения, «предмет каталога → тип изображения» — этап 4.4 и Д1.
- Инвентарь, кукла, экипировка, расчёт КД персонажа — этап 4.3 (здесь — только данные для них).
- Рост заклинаний — этап 3.5.

## Известные риски

- Обычное снаряжение на DnD.su — не отдельные страницы, а таблицы в статьях: парсер таблиц, а не карточек. Проверять по каждой таблице число строк.
- Названия совпадают между категориями (например, «Щит» — заклинание и доспех) — ID различаются категорией (`spell:shield`, `item:shield`), поиск по всему каталогу показывает категорию.
- Разновидности рас и повторы текста — источник дублей механики (ловушка v0.1).
- Варианты рас из разных книг (например, эльфы MToF) и записи только для 2024 — фильтр редакции Р12, расхождения — в отчёт.
- Цены «варьируется», вес «—» — `null` с пометкой, а не 0.
- `npm run dist` в рабочей папке — `EBUSY` (обход в отчёте этапа 0).
- Диск C — по минимуму (раздел 13.5).

## Спросить автора, а не решать самому

Решено автором 2026-10-27:

1. **Компоненты заклинаний, которых нет в списках снаряжения** (гуано, сера, алмаз за 300 зм…) заводятся предметами каталога вида «компонент заклинания» (`item:bat-guano`) из проверенных данных `data/reviewed/spells/`, без страницы DnD.su, с пометкой источника (Р60).
