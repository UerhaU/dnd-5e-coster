- **Навыки, языки, состояния** — схемы `skill/v1`, `language/v1`, `condition/v1` без `rules_json`; английские названия языков и состояний — `data/reviewed/character/names.json` (как Р62); повтор языка в другой книге — один объект с письменностью по книгам; диалекты — объекты со связью `dialect_of`.
- **Навыки и языки рас** — коды в `race-rules/v1` остаются, при сборке становятся связями `skill_proficiency` / `language`; цель без объекта — ошибка сборки. Так ревизии рас не меняются.
- **Черты** — схемы `feat/v1` и `feat-rules/v1`; требования — группы «И» из условий «ИЛИ», цели — ID (раса, черта, предыстория) и связь `prerequisite`; неразобранное условие — `kind: text`; заклинания по названию — ID и связь `feat_spell`; выбор заклинания — текстом.
- **Смешанный выбор владений** — общий вид `{count, from: [skill|tool|tool_group]}` у рас (`proficiencyChoices`, необязательное), предысторий и черт (`mixed`).
- **Предыстория → черта** — связь `grants_feat` по ссылкам из раздела «Умение».
- **Подписи языков** — только у объектов-языков (`race-codes.ts` — коды).
- **Предыстории** — схемы `background/v1` и `background-rules/v1`; навыки, языки, инструменты — ID; транспорт — вид; снаряжение — части строки, сопоставление по названию и `data/reviewed/character/equipment.json`, связь `starting_equipment`; статьи «Адаптация предысторий» — вид `adaptation`.

## Что важно знать следующему этапу

Часть В:

- Классы заклинания для конструктора (этап 4) — связи `spell_class` / `spell_subclass` или `spell_index_classes` (`access`: `standard`, `optional`, `subclass`); `data.classes` и `data.subclasses` остаются как были (ревизии заклинаний не трогались).
- Новое название подкласса в фильтре заклинаний DnD.su — `spellListName` в `subclasses.json`, иначе ошибка полной сборки.
- Связи не входят в ревизию: новые связи у старых объектов не дают новых ревизий (так части А и В не меняли ревизии рас и заклинаний).
- Playwright на тестовом каталоге локально, как в CI: `npm run catalog:build -- --fixtures --strict --out <файл>`; собрать программу во внешнюю папку (`npx electron-builder --win dir --x64 -c.directories.output=D:\programm\koster-release`), скопировать `win-unpacked` и заменить в копии `resources/catalog.db` тестовым; `KOSTER_APP_DIR=<копия> npx playwright test` (в `apps/desktop`).
- Python на Windows пишет файлы с CRLF — `prettier --check` тогда падает; писать с `newline="\n"` или прогонять `prettier --write`.

Часть Б:

- Конструктору (этап 4): `rules.table[level - 1]` — всё по уровню (бонус мастерства, ключи особенностей, столбцы, ячейки); особенности — `data.features` (`levels`, `optionalRule`); подкласс — `rules.subclass.level` и `featureLevels`; мультикласс — `rules.multiclass` и `spellcasting.progression`.
- Разбор страницы класса — по заголовкам: h2 с якорем через точку — подкласс; h2 `hide-next` внутри умений — список вариантов; h3 с «N-й уровень, умение» — особенность. Новый столбец таблицы — в `CLASS_TABLE_COLUMNS` и `COLUMN_KEYS` (`normalize-class.ts`), иначе ошибка сборки; новая книга подкласса — в `BOOKS` (`items/sources.ts`).
- Автоформат в рабочей папке превращает `‎` в регулярных выражениях в сами символы (`items/sources.ts`, `parse-class-page.ts`) — работает так же, рядом комментарий.

Часть А:

- Новая справочная категория со списком: добавить её в `REFERENCE_LIST_CATEGORIES` (`shared/api/catalog.ts`), фильтры — в `referenceListQuerySchema` и `reference-queries.ts` (строка `detail` — своя у категории), экран и маршрут появятся сами (`App.tsx` перебирает список). Классам (часть Б) этот вид может не подойти — у рас и заклинаний свои списки.
- Требование черты `kind: class` хранит `class:…` из `CLASS_IDS`; когда появятся объекты классов, добавить их в связь `prerequisite` в `featLinks` (`collect-feats.ts`).
- `race-rules/v1` получил необязательное `proficiencyChoices`: новые поля в старой схеме — только необязательными и только там, где они есть, иначе меняются ревизии всех рас.
- Порядок сборки этапа 3: справочные → предыстории → черты (им нужны расы, предыстории, заклинания) → связи `grants_feat` предысторий.

- Добавить категорию: `CATEGORIES`, `CATEGORY_NAMES_RU` (`shared/catalog/entity.ts`), `CategoryIcon`, `CATEGORY_LABELS` (`ui/catalog/search-format.ts`), карточку в `entityResponseSchema`, вариант в `CatalogEntity` и `LinkKind` (`importer/build/catalog-entity.ts`), запись индекса в `write-catalog.ts`, строку в отчёт сборки. `/api/catalog/categories` перечисляет категории сам — тест `catalog.test.ts` ждёт точный список.
- `parseCardPage` (`character/parse-background-page.ts`) годится для черт: `params` — строки над описанием («Требование: …»), `labeled` — абзацы «Метка: …» (двоеточие бывает внутри и после `<strong>`), разделы с пустым заголовком склеиваются с прошлым.
- Основы слов из `races/parse-race-rules.ts` (`SKILL_STEMS`, `TOOL_STEMS`, `TOOL_GROUP_WORDS`, `found`, `countIn`) теперь экспортируются. Языки предысторий сопоставляются по первым 5 буквам названия объекта языка (`backgroundLookup`), неоднозначные основы отбрасываются.
- В JS `\b` не работает с кириллицей — для «15 зм» нужен `(?![а-яё])`.
- Тестовые страницы этапа 3 пересобираются скриптом; при добавлении случая — дописать `FIXTURE_PAGES` в `make-character-fixtures.ts`. В тестовом каталоге связи `starting_equipment` к предметам, которых нет в тестовом снаряжении, — предупреждения (40 вместо 34).
- `npm run catalog:build` без `--fresh` с прошлым `catalog.db` здесь не запускался — рабочий `apps/desktop/resources/catalog.db` и журнал не тронуты.
