# Ручная проверка выборки заклинаний (этап 1, Issue #12)

Дата: 2026-10-27. Проверял чат «Тестирование» (раздел 13.2). Этап этим не принимается — принимает только автор.

## Как проверено

- **Программа:** окно «Костёр» из `npm run dev` (уже было запущено, автор разрешила использовать). Полный каталог версии 2, 524 заклинания. Данные карточек взяты из API dev-сервера (`/api/catalog/entity/spell:…`) — то же, что получает экран карточки.
- **Сайт:** 30 страниц `5e14.dnd.su` во встроенном браузере, по одной за раз. Со страницы брался блок заклинания до «Комментариев».
- **Шапка** (уровень, школа, ритуал, время, дистанция, компоненты, длительность, классы, подклассы, источники) — сравнена по полям.
- **Описание и «На больших уровнях»** — сравнены целиком: текст приведён к нижнему регистру, «ё» → «е», убраны пробелы и знаки препинания, затем сравнены длина и хэш. Совпадение значит: все слова и числа те же и в том же порядке. Расхождения в запятых и в «ё» внутри описания этим способом не ловятся.
- **Подписи карточки** («(ритуал)», «(TCE)», «Цели: …», «Механика проверена», метки, «А (…)») — по коду `packages/ui/src/catalog/spell-format.ts`, `SpellCard.tsx`, `TextBlocks.tsx` на данных из API.
- **Поиск и фильтры** — запросами к `/api/catalog/spell` (те же параметры, что ставит экран списка).
- **Глазами окно не осматривалось:** computer use в этой сессии выключен. Автор внешний вид проверила сама («вроде работает»). Поэтому вёрстка таблиц, переносы длинных строк и поведение кнопок в окне в этом отчёте не проверены.

## Замечания по интерфейсу и поиску

1. **Фильтр по классу не видит доступ через подкласс** (нужно решение автора). Все 15 заклинаний EGW (дюнамантия) не имеют классов, только подклассы волшебника. Фильтр «Волшебник» их не показывает. Так же «Огненный шар» не попадает в фильтр «Жрец», хотя есть в домене света. Для домена это верно, а для дюнамантии автор, может быть, захочет, чтобы они попадали под «Волшебник» (как подкласс-only или отдельной пометкой).
2. **Поиск «ё/е» работает:** «перышком»/«пёрышком», «черные»/«чёрные», «огнем»/«огнём», «темная звезда» — находят одно и то же. Регистр не важен («ПОСЛАНИЕ»), пробелы по краям обрезаются.
3. **Порядок результатов:** по запросу «щит» точное совпадение «Щит» стоит третьим, после «Щит веры» и «Огненный щит». Не ошибка, но точное совпадение названия разумно ставить первым.
4. **Длинный запрос:** API принимает до 200 символов, а у поля поиска нет ограничения длины. Если вставить в поиск больше 200 символов, вместо списка будет «Не удалось загрузить: Неверные параметры запроса». Мелочь: можно поставить `maxLength={200}` на поле.
5. **Спецсимволы** (`"`, `*`, `щ*`, `-магии`, `AND`) не ломают поиск: ошибок нет, `*` и `"` показывают весь список.
6. **Кнопка «← К списку»** делает `navigate(-1)`, то есть возвращает на прошлый экран вместе с запросом и фильтрами (после исправления в e3c54ea). Глазами в окне не проверено. Если карточку открыть без истории (например, в будущем — по ссылке из другого места), кнопка никуда не уведёт.
7. **Ссылки на DnD.su** у двух источников одного заклинания (№ 5, 14) ведут на одну и ту же страницу — так устроен сайт, не ошибка.
