### Часть А: данные и механика

- `packages/shared/src/catalog/item.ts` — схема `item/v1`: вид (`kind`), группа (`category`), цена в медных (`cost.cp`, исходный текст `cost.text`), вес в фунтах, количество в упаковке («Стрелы (20)»), `optionalRule` (вариант правил, нужно разрешение мастера), эпоха огнестрельного оружия, столбцы исходной строки таблицы, состав набора, описание блоками без HTML.
- `item-rules.ts` — механика `item-rules/v1` в `rules_json`: **оружие** (простое/воинское, рукопашное/дальнобойное, урон и тип, свойства с дистанцией, костью «универсального» и числом выстрелов «боекомплекта», ID боеприпаса), **доспех** (КД = база + Лов с пределом, требование Силы, помеха Скрытности, надевание и снятие), **щит** (+2, надевание и снятие).
- `item-codes.ts` — справочники: виды предметов (9), группы (виды оружия и доспехов, фокусировки, инструменты — 13), свойства оружия (12, включая «боекомплект» и «очередь» DMG). Таблицы `item_kinds`, `item_categories`, `weapon_properties`.
- База: `item_index` (вид, группа, цена, вес, вариант правил, тип урона), `item_index_properties`; миграция `0003_item_index`. Связи в `content_links`: `contains` (состав набора, 68 ссылок) и `uses_ammunition` (оружие → боеприпас, 19).
- **Английские названия** (Р11): в таблицах DnD.su их нет — заданы вручную в `data/reviewed/items/names.json` (по PHB/DMG; там же группа для дополнительного оружия, боеприпас оружия и заголовки описаний, если они не совпадают с названием). Состав наборов — `data/reviewed/items/packs.json` (по тексту DnD.su; предметы, которых нет в таблицах — «кадило», «леска» — только названием).
- Описания: абзацы «Термин. Текст» и разделы h3 статьи сопоставляются с предметом по названию, по «<название> доспех», по группе («Магическая фокусировка») и по `descriptionTerms`.

### Часть А: импорт, API, экраны

- Импортёр: `packages/importer/src/items/` (`parse-article.ts` — таблицы с группами и двумя половинами, `parse-values.ts` — цена, вес, урон, свойства, КД, `normalize-items.ts`, `describe.ts`, `sources.ts`), `build/collect-items.ts`. Сборка пишет заклинания и снаряжение в один `catalog.db`; `CatalogEntity` стал общим для категорий (`build/catalog-entity.ts`), индексы категорий — `build/write-index.ts`.
- Источники снаряжения — те же строки `sources`, что у заклинаний (PH14 — одна строка с номером фильтра 102); новые: DMG14, TOA, OTA, RLW, WDH, SDQ, COS.
- API: `GET /api/catalog/item` (поиск, фильтры `kind`, `category`, `property`, `damageType`, `source`, `optionalRule`, сортировка по названию, цене, весу; неизвестная цена — в конце), `GET /api/catalog/item/facets`. Карточка `GET /api/catalog/entity/:id` — общая схема `entityResponseSchema` с вариантом по категории (`spell` | `item`) и полем `links` (связи в обе стороны).
- Экраны: «Справочник» → «Снаряжение» (`ItemList.tsx`: поиск, 7 фильтров, пометка «вариант правил»), общая карточка `EntityCard.tsx` с телом по категории (`ItemCard.tsx`: цена, вес, урон и свойства или КД, Сила, Скрытность, время; состав набора ссылками; «Используется оружием», «Входит в наборы»). Общие части списков и карточек вынесены в `ListControls.tsx` и `CardParts.tsx`; экран заклинаний переведён на них.

## Предлагаемые решения для раздела 2

- **Английские названия снаряжения задаются вручную** (`data/reviewed/items/names.json`): в таблицах DnD.su их нет, а ID строится по ним (Р11). Названия — по PHB/DMG, это не текст правил. Строка без названия в файле не попадает в каталог и отмечается ошибкой сборки.
- **Механика снаряжения — `item-rules/v1`** (`packages/shared/src/catalog/item-rules.ts`): оружие, доспех или щит; заполняется разбором таблиц (`review_status: parsed`, `automation: assisted`). Общий словарь механики уточнит движок правил на этапе 4 (как Р49).
- **Кэш статей «Инвентарь»** — `storage/dndsu-articles/` (`--items-cache`), по образцу Р50.
- **Карточка объекта — одна схема с вариантом по категории** (`entityResponseSchema`) и полем `links` со связями в обе стороны; клиент: `api.entity(id)` вместо `api.spell(id)`.
- **Дополнительное оружие из приключений и всё со статьи «Огнестрельное оружие и взрывчатка» — `optionalRule: true`** (как в v0.1); в списке — пометка «вариант правил», фильтр «Только обычные правила».
